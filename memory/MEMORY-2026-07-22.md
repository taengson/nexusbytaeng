## 🔍 Analysis & Diagnosis (Updated)
- **Root Cause**: It's not just a transport issue, but an **Output Buffering** problem.
- **Evidence**: Hermes session logs show that the user's questions were received and responses were generated, but these responses are not appearing in the UI.
- **Diagnosis**: When `hermes chat` detects it's not running in a TTY (i.e., running in a Pipe), it switches to `Full Buffering` mode. The responses are generated but remain in the OS stdout buffer, never reaching the `AgentProcessManager.read()` call.

## 🛠️ New Fix Plan: Forced Unbuffering
- **Objective**: Force the process to flush stdout immediately regardless of the transport type.
- **Action 1**: Wrap the command with `stdbuf -i0 -o0 -e0` (or equivalent) to disable all buffering.
- **Action 2**: Review `StreamParser` to ensure it doesn't hold onto data waiting for a newline if the output is fragmented.
- **Action 3**: Verify that `AgentProcessManager` reads are not blocking in a way that hides partial responses.

## 🚀 Expected Outcome
- Full synchronization between Hermes session state and UI.
- Real-time streaming of responses without waiting for buffer fills or newlines.
