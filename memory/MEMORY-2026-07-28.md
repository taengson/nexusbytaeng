# 📅 MEMORY-2026-07-28: ACP UI/UX 버그 분석 리포트

## 🔍 [리뷰어] ACP 응답 소실 및 Think 쪼개짐 현상 분석

사용자 테스트 결과, **AI 응답(Response)이 보이지 않고 Think 내용이 여러 위젯으로 쪼개지는 현상**이 발견되었습니다. 이에 대한 근본 원인을 분석한 결과입니다.

### 🔴 문제 1: AI 응답(Response) 소실 (또는 Thought 위젯에 병합)
- **현상**: `💭 Think` 내용은 출력되나, 실제 AI의 최종 응답 텍스트가 화면에 나타나지 않음.
- **원인**: `SessionWorkspace.update_last_ai_message`의 위젯 추적 로직 결함.
    - `_active_ai_widget`이 존재하면 `sender` 타입에 관계없이 무조건 해당 위젯에 `append_text`를 수행함.
    - **흐름**: `Thought` 청크 수신 $\rightarrow$ `_active_ai_widget`에 `thought` 위젯 할당 $\rightarrow$ `Response` 청크 수신 $\rightarrow$ `_active_ai_widget`이 존재하므로 **`thought` 위젯 내부에 응답 텍스트를 추가**함.
    - 결과적으로 `sender="ai"`인 전용 위젯은 생성되지 않고, 모든 텍스트가 `thought` 위젯 하나에 섞여 들어가거나 시각적으로 누락됨.

### 🔴 문제 2: Think 내용 쪼개짐 (Widget Fragmentation)
- **현상**: 하나의 생각(Thought) 흐름이 하나의 위젯에 담기지 않고, 청크 단위로 여러 개의 위젯으로 분리되어 출력됨.
- **원인**: `_handle_acp_message` 내 `agent_thought_chunk` 처리 시 무조건적인 리셋.
    - `elif update_type == "agent_thought_chunk":` 블록 진입 시 매번 `self._active_ai_widget = None`을 실행함.
    - 이로 인해 `update_last_ai_message`는 매 청크마다 `else` 블록을 타게 되어 **매번 새로운 `MessageWidget(sender="thought")`을 생성하여 mount**함.

## 🛠️ [개발자] 수정 가이드라인

### 1. `update_last_ai_message` 조건 강화
`self._active_ai_widget`이 있더라도 **`sender`가 일치할 때만** 텍스트를 추가하도록 수정하십시오.
```python
# 수정 전
if self._active_ai_widget:
    self._active_ai_widget.append_text(text + " ")

# 수정 후
if self._active_ai_widget and self._active_ai_widget.sender == sender:
    self._active_ai_widget.append_text(text + " ")
```

### 2. `agent_thought_chunk` 리셋 로직 최적화
매 청크마다 리셋하지 말고, **현재 활성 위젯이 `thought` 타입이 아닐 때만** 리셋하십시오.
```python
# 수정 전
elif update_type == "agent_thought_chunk":
    thought = content.get("text", "")
    self._active_ai_widget = None 
    self.update_last_ai_message(thought, sender="thought")

# 수정 후
elif update_type == "agent_thought_chunk":
    thought = content.get("text", "")
    if not self._active_ai_widget or self._active_ai_widget.sender != "thought":
        self._active_ai_widget = None # 또는 직접 할당 로직
    self.update_last_ai_message(thought, sender="thought")
```

## 🔍 [리뷰어] 로그 추적성 및 UX 완결성 개선 제안

동작 구현은 완료되었으나, 나중에 로그를 다시 봤을 때 맥락을 알 수 없는 '정보 부족' 상태입니다. 이를 해결하기 위한 추가 개선 사항을 정의합니다.

### 🔴 현상 및 문제점
1. **세션 모드 식별 불가**: 로그 파일에 어떤 `ConnectionMode`가 사용되었는지 기록되지 않아, 분석 시 모드 식별이 불가함.
2. **ACP 세션 ID 누락**: ACP 연결 시 할당받은 `sessionId`가 기록되지 않아, 서버 로그와 매칭하여 추적하는 것이 불가능함.
3. **쉘 입력 명령어 소실**: 쉘 모드에서 사용자가 입력한 명령어 자체가 채팅창과 로그에 남지 않고 결과만 출력되어, 결과값이 무엇에 대한 응답인지 알 수 없는 '블라인드 상태'임.

### 🛠️ 개선 방향 (Action Items)
1. **세션 모드 기록**: `logger.start_session()` 호출 시 또는 세션 시작 시점에 현재 `ConnectionMode`를 로그에 명시적으로 기록.
2. **ACP 세션 ID 기록**: ACP 핸드셰이크 성공 후 `sessionId` 획득 시점에 `logger.log_event("system", "ACP", f"Session ID: {session_id}")` 기록.
3. **쉘 입력 명령어 표시**: `SessionWorkspace.on_input_result`에서 `is_shell=True`인 경우, 결과 출력 전 사용자가 입력한 명령어를 UI(채팅창)와 로그에 먼저 표시.

### ⚠️ 보완 제안 (2건)

**1. `on_close` $\rightarrow$ `on_remove` 변경 권장**
- `SessionWorkspace`는 `Container` 위젯이며, Textual에서 `on_close`는 `App` 레벨 이벤트입니다.
- 위젯 제거 시에는 `on_remove`가 더 적절합니다.
- **현재**: `def on_close(self) -> None:`
- **권장**: `def on_remove(self) -> None:`

**2. 쉘 명령어 처리 방식 — 두 번 전송 vs 필드 추가**
- 리뷰어의 계획은 `InputResult`를 두 번 보내는 방식(명령어 전송 $\rightarrow$ 결과 전송)입니다.
- 대안으로 `InputResult`에 `command` 필드를 추가할 수 있으나, 기존 코드 변경이 많아 리스크가 큽니다.
- **추천**: 리뷰어의 계획(두 번 전송) 유지 — 기존 코드 변경이 적어 안전함.

### 📝 [개발자] 리뷰어 판단 요청
1. `on_close`를 `on_remove`로 변경할지 의견 부탁드립니다.
2. 쉘 명령어 처리 방식은 리뷰어의 계획(두 번 전송)으로 진행해도 될지 확인 부탁드립니다.

### ❌ 이슈 2: AI 응답 시각적 정렬 불량 — **리뷰어 분석 오류, 실제 문제 다름**

리뷰어가 "CSS 스타일 부족"이라고 분석했으나, 실제 로그에서 확인된 문제는 **타이머 동작 실패로 인한 로그 분절**입니다.

**실제 로그 증거**:
```
[10:10:33] [AI] AI: 태영이야. NexusByTaeng 프로젝트에서...
[10:10:33] [AI] AI:  강조
[10:10:33] [AI] AI: 했지
[10:10:33] [AI] AI: . 한국어
[10:10:33] [AI] AI: 로 대화
[10:10:33] [AI] AI: 하고, 간
[10:10:33] [AI] AI: 결한 응답
[10:10:34] [AI] AI:  선호
[10:10:34] [AI] AI: .
```

**한 문장이 8~9개로 쪼개져 로깅**되고 있습니다. 이는 `set_timer(2.0, _finalize_ai_logging)`가 제대로 동작하지 않아, 매 청크마다 별도 로그가 기록되고 있기 때문입니다.

**근본 원인**: `ACPClient`의 `_listen_loop`가 별도 asyncio task에서 실행되며, `on_message` 콜백을 직접 호출합니다. 이때 `set_timer`가 **Textual 이벤트 루프 외부**에서 호출되면 타이머가 제대로 등록되지 않습니다.

**해결 방안**:
- `set_timer` 대신 `self.app.call_from_thread()`를 사용하여 Textual 이벤트 루프에서 타이머 설정
- 또는 응답 완료 신호를 감지하여 즉시 `_finalize_ai_logging` 호출
