### 📂 프로젝트 폴더 및 파일 구조
단일 파일 작성을 금지하며, 다음과 같이 역할별로 나누어 작업합니다.
```
src/
 ├─ main.py                # 앱 진입점 및 NexusApp 정의
 ├─ screens/               # 화면 단위 모듈
 │   ├─ home_screen.py     # 홈 화면 (HomeView)
 │   └─ session_screen.py  # 세션 화면 (SessionView)
 ├─ widgets/               # 재사용 가능한 UI 컴포넌트
 │   ├─ project_tree.py    # 프로젝트 파일 트리 위젯
 │   ├─ chat_elements.py   # 메시지 버블, 채팅 컨테이너
 │   └─ input_area.py      # 통합 설정이 포함된 입력창 및 퀵 패널
 ├─ styles/                # 스타일시트
 │   └─ nexus.tcss         # 전체 테마 및 컴포넌트 스타일 정의
 └─ core/                  # 비즈니스 로직 추상화 (현재는 스켈레톤만)
     └─ state.py           # 현재 연결 모드 등 전역 상태 관리
```

### 🛠️ 단계별 구현 상세
1. **기반 구축**: 폴더 구조 생성 및 `NexusApp` 라우팅 기초 설계.
2. **홈 화면 (`HomeView`)**: 4가지 연결 메뉴(`로컬 AI 연결`, `네트워크 연결`, `GEMINI-CLI 연결`, `OpenCode 연결`) 구현.
3. **세션 레이아웃 (`SessionView`)**: 좌측 프로젝트 트리 + 우측 채팅창 분할 구조 설계.
4. **입력창 및 설정 패널**: ⚙️ 버튼 클릭 시 퀵 설정 패널(QuickSettingsPanel) 팝업 제공. 4가지 연결 옵션 선택 시 입력창 UI(색상, 아이콘, 프리픽스 등) 즉시 동적 변경 구현.
5. **시각적 폴리싱**: `.tcss`를 통한 카드형 메시지 디자인 및 전문가용 다크 테마 완성.

### 📝 제약 사항 (Constraints)
- **모듈화**: 모든 기능은 위 트리 구조에 따라 분리하여 작성하며, 하나의 파일에 전체 기능을 넣지 않음.
- **기능 범위**: 프로젝트 파일 트리를 제외한 실제 통신/연산 로직(LLM API 등)은 추가하지 않고 Mock 데이터로 대체함.
- **UI/UX 집중**: 홈 ➜ 세션 전환 흐름과 모드 변경 시의 입력창 시각적 피드백 구현에 집중함.

### 🚀 추가 설계: 홈 화면 및 작업 공간 분리 계획

- **레이아웃 구조**: 앱의 중심 허브 역할을 하는 `HomeScreen`을 메인 영역에 배치하고, 작업용 `TabbedContent`를 별도로 구분하여 배치.
- **작업 공간 격리**: 소스 트리(Project Tree)는 탭 내부의 `SessionWorkspace`에만 포함시켜, 홈 화면이나 공통 영역에서 노출되지 않도록 설계.
- **기능 중심 탭 구성**: `TabbedContent` 내의 탭 제목은 단순 숫자가 아닌 기능 중심(예: "로컬 AI 연결", "Gemini 분석")으로 동적 생성.
- **홈 화면 역할**: 프로젝트 개요, 전체 세션 목록, 새 세션 생성 버튼 등 대시보드 기능 수행.

## 🛠️ 작업 업데이트 (2026-07-15)

### 1. 레이아웃 및 내비게이션 수정
- **홈 화면 복구**: `HomeScreen`을 `Screen`에서 `Container` 위젯으로 변경하여 `#main-area` 내에 배치. 이제 앱 시작 시 홈 화면이 정상적으로 표시됨.
- **전환 로직 구현**: `HomeScreen` 버튼 클릭 시 `enter_session()`을 통해 홈 화면을 숨기고 `TabbedContent` 워크스페이스를 활성화하는 흐름 구축.
- **홈 복귀 기능**: `h` 키 바인딩을 통해 워크스페이스에서 다시 홈 화면으로 돌아가는 `action_go_home` 구현.
