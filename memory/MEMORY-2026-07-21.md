## 🚀 Future Architecture: Universal Agent Communication (Toad-inspired)
- **Core Problem**: `Warning: Input is not a terminal (fd=0)` indicates that agents like Hermes require a TTY toApplicants a real terminal environment, ensuring `isatty()` checks pass.
- **Architecture Goal**: Build a robust, generic communication bridge for any CLI-based agent.
- **Key Design Pillars**:
    1. **PTY-based Infrastructure**: Use Pseudo-terminals (`pty` module) to emulate a real terminal environment, ensuring `isatty()` checks pass.
    2. **Stream Refinement**: Implement a `StreamCleaner` to filter ANSI control codes and handle chunked binary data, ensuring only clean text reaches the UI.
    3. **Async I/O Bridge**: Standardize an asynchronous pipeline: `PTY Stream` $\rightarrow$ `Cleaner/Parser` $\rightarrow$ `UI Event Queue`.
- **Implementation Roadmap**:
    - [x] Phase 1: Implement `TtyProcessManager` for PTY-based subprocess control.
    - [x] Phase 2: Create `StreamParser` for ANSI filtering and chunk merging.
    - [x] Phase 3: Replace `AgentProcessManager` with the new TTY-based bridge in `SessionWorkspace`.
    - [ ] Phase 4: Full integration with `ChatLogManager` for end-to-end flow verification.
